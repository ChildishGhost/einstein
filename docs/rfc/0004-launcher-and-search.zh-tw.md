# RFC 0004：啟動器視窗與搜尋

## 摘要
記錄 `db39f26` 時啟動器的行為：一個無邊框、永遠置頂、以全域快捷鍵切換的視窗，每次按鍵都跨所有外掛搜尋，以一次模糊比對排序合併後的結果，並完全以鍵盤操作。其外觀與版面另行處理。

## 動機
這些需求是使用者熟悉的行為；變更啟動器的 RFC 會逐項明確保留或變更，它們也是一致性檢查的依據。

## 需求

### 視窗
- **R1** — 啟動器是單一個無邊框、永遠置頂的視窗，建立時隱藏，並以隱藏取代銷毀；在 Linux 上使用 `toolbar` 視窗類型。
- **R2** — 全域快捷鍵切換視窗：Linux 為 Alt+Space，其他平台為 Ctrl+Space。顯示時會置中並取得焦點；視窗可見且有焦點時按下快捷鍵則隱藏。
- **R3** — 應用程式選單提供 Restart（RFC-0002/R6）、DevTools 與標準編輯指令。

### 搜尋
- **R4** — 輸入每次變更都立即送出搜尋；輸入為空時隱藏結果清單。
- **R5** — 所有執行的引擎（RFC-0003/R10）的結果會合併，依 `title` 與 `description` 的模糊比對一起排序（只重排、不過濾），並截取一個固定的小數量（`db39f26` 時為 10；此數值不屬於契約）。查詢為空時，結果維持引擎順序。
- **R6** — 一次搜尋的所有結果一起送達。
- **R7** — 只有當回覆的 `term` 等於目前輸入時才顯示；過期的回覆會被丟棄。

### 鍵盤與滑鼠
- **R8** — Up / Ctrl+P 與 Down / Ctrl+N 移動選取，並循環；滑鼠移到結果上即選取該結果。
- **R9** — Tab 將輸入替換為所選結果的 `completion`，沒有時則用其 `title`。
- **R10** — Enter 或點擊會啟用所選結果：有 `event` 時送給外掛（RFC-0003/R11），接著清空輸入並隱藏視窗；沒有 event 但有 `completion` 時則改為補全。
- **R11** — Esc 清空輸入並隱藏視窗。
- **R12** — 重新開啟視窗時保留先前的輸入；只有 Esc 或啟用結果會清空。

## 設計
- Renderer（Vue 3）負責輸入、選取與繪製；主行程負責視窗（RFC-0002/R16）；排序與結果上限在外掛主機中處理，使用 threshold 1.0 的 Fuse。
- 除了 Esc 之外，按鍵綁定都需要完全符合所列的修飾鍵。
- 版面與外觀另行記錄於之後一份關於啟動器視覺設計的追溯式 RFC。

### `db39f26` 時已知的缺口（非決策）
- 視窗失去焦點時不會隱藏；失焦隱藏是預期中的行為，但從未實作。
- 每次按鍵都執行所有引擎；沒有取消機制。
- 結果變更時不會重設選取索引；沒有結果時按方向鍵會得到 `NaN`。
- 列以索引而非 `id` 作為 key。
- 沒有無障礙語意（role、label、圖示 alt 文字）；沒有 i18n。
- 快捷鍵固定，且未檢查是否註冊成功。
- 輸入框只在首次掛載時取得焦點，而非每次顯示時。

## 驗證
追溯式（RFC-0001/R16）：描述 `db39f26` 時的程式碼；不受測試覆蓋檢查約束。之後變更這些需求的 RFC，須在「與較早 RFC 的關係」中列出。
