# RFC 0009：快速動作

## 摘要
搜尋結果可以提供快速動作：主要動作之外的次要動作，例如「開啟」旁的「複製」。RFC 0008 的 Deno UI 會在被選取結果的列中顯示其動作；使用者以滑鼠或左右方向鍵挑選，並以 Enter 或點擊執行。執行動作會將其事件送給所屬外掛，接著清空輸入並隱藏啟動器，除非該動作要求保持開啟。

## 動機
目前一個結果只有一個動作（RFC-0003/R11）。每個項目有多個實用動作的外掛，例如可輸入也可複製的密碼項目，必須為每個動作回傳一個結果，讓清單變得擁擠。`feature/quick-action` 分支在 2022 年開始這項功能，但只支援滑鼠；Deno UI 本來就在重建（RFC 0008），因此快速動作在那裡設計，並如 RFC 0004 所要求以鍵盤為先。

## 需求
- **R1** — 搜尋結果可以帶有 `quickActions`，為 `{title, icon?, event: {type, data?}, keepOpen?}` 的清單。`QuickAction` 型別在兩種外掛主機上都由 `einstein` 匯出。
- **R2** — Deno UI 在被選取結果（RFC-0004/R8）的列中，依給定順序顯示其所有快速動作，一行放不下時換到後續各行；其他列不顯示動作。
- **R3** — 游標位於輸入尾端時，按右鍵會突顯被選取結果的第一個快速動作。之後左右鍵依序跨行移動突顯，停在最後一個動作；在第一個動作上按左鍵會移除突顯並回到輸入框。其他情況下，左右鍵移動游標。
- **R4** — 選取另一個結果（上、下鍵或滑鼠停留）、變更輸入，或按 Tab（如 RFC-0004/R9 補全被選取的結果）都會移除動作突顯。
- **R5** — Enter 執行被突顯的動作；點擊動作即執行它。沒有被突顯的動作時，Enter 維持 RFC-0004/R10 的行為。
- **R6** — 執行動作會將該動作 `event` 中的 `{pluginUid, type, data}` 送給回傳該結果的外掛，路徑與啟用結果相同（RFC-0003/R11）。
- **R7** — 動作執行後，清空輸入並隱藏啟動器。帶有 `keepOpen: true` 時，啟動器保持開啟，輸入、突顯與結果維持原樣；不會重新搜尋。
- **R8** — 動作的 `icon` 依 RFC-0008/R4 的規則顯示：只接受 `plugin://` 與 `data:` URL。
- **R9** — 缺少 `title` 或 `event.type` 的動作會被略過；該結果的其他動作照常顯示。

## 設計
- **資料：** 動作隨結果經由既有的 `search` → `plugin:performSearch` → `searchResult` 路徑傳遞（RFC-0002/R13）；主行程與外掛主機原樣轉送。UI 本來就知道每個結果的 `pluginUid`。
- **狀態：** UI 在被選取結果的索引旁保存 `actionIndex`；`-1` 表示沒有突顯。按鍵處理是（輸入、游標、選取、actionIndex、按鍵）的純函式，測試直接驅動它。
- **游標規則（R3）：** 動作在視覺上位於文字之後，因此在文字尾端再按右鍵會進入動作，打字也不會被打斷。
- **Electron UI：** 它忽略 `quickActions`；外掛可在兩種主機上回傳動作，不必檢查執行的是哪個 UI。

## 與較早 RFC 的關係
Electron UI 保留所有較早的需求。對 Deno UI 而言，未列出的需求皆保留：

- RFC-0003/R11 — 變更：結果還可以帶有 `quickActions`（R1）；啟用結果本身不變。
- RFC-0003/R14 — 變更：API 新增 `QuickAction` 型別（R1）。
- RFC-0004/R8 — 保留；選取結果時也會顯示其動作（R2）。
- RFC-0004/R9 — 保留：Tab 補全被選取的結果，有動作被突顯時亦然（R4）。
- RFC-0004/R10 — 變更：有被突顯的動作時，Enter 執行該動作（R5）。
- RFC-0004/R11 — 保留：Esc 清空輸入並隱藏啟動器，有動作被突顯時亦然。
- RFC-0004/R12 — 保留。
- RFC-0007/R2 — 保留：視窗高度隨較高的列調整。
- RFC-0007/R3 — 變更：被選取的列也容納其動作，需要幾行就佔幾行（R2）。
- RFC-0008/R4 — 保留，也適用於動作圖示（R8）。

## 替代方案
- **左右鍵一律在動作間移動：** 按鍵規則最簡單，但游標只能以 Home、End 或滑鼠移動。
- **Alt+左與 Alt+右：** 不與游標衝突，但使用者必須學習組合鍵。
- **以按鍵（例如 Ctrl+K）開啟動作清單：** 可容納大量動作，但在要求前看不到它們。
- **Alt+1…9 對應前九個動作：** 對熟悉的動作最快，但沒有額外標示就看不出哪個數字對應哪個動作。
- **動作只佔一行，捲動或以「+k」標記截斷：** 列高維持一致，但會隱藏動作。
- **Esc 先移除動作突顯：** 隱藏要多按一次，與啟動器其他所有狀態不同。
- **`keepOpen` 動作後重新搜尋：** 結果反映動作造成的變更，但清單可能在使用者游標下跳動。
- **只要有一個動作無效，就忽略該結果的所有動作：** 較嚴格，但外掛的一個錯誤就會隱藏該結果的所有動作。
- **只支援滑鼠，如 `feature/quick-action`：** 違背 RFC 0004 以鍵盤為先的模式。
- **兩個 UI 都支援：** 意味著在 RFC 0008 維持不變的 UI 中再實作一次。

## 驗證
測試涵蓋 R1–R9：匯出的型別（R1）；負責顯示、移動、清除與執行的按鍵處理函式（R2–R5）；經由主行程送出的事件（R6）；隱藏、清空與 `keepOpen`（R7）；圖示規則（R8）；略過無效動作（R9）。
